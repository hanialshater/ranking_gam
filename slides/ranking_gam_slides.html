Library Architecture

What is a Tower?

A tower is a small neural network that processes a single feature and outputs a scalar score contribution.

Key insight: Each tower is a 1D function fj(xj) — you can plot it as a response curve and interpret it directly.

PaperTower — The Workhorse

class PaperTower(nn.Module):
    def __init__(self, in_dim=1,
                 hidden_dims=[16, 8],
                 activation="silu",
                 residual=True):
        # Build MLP layers
        layers = []
        prev = in_dim
        for h in hidden_dims:
            layers += [nn.Linear(prev, h),
                       get_activation(activation)]
            prev = h
        layers.append(nn.Linear(prev, 1))
        self.net = nn.Sequential(*layers)

        # Optional skip connection
        if residual:
            self.skip = nn.Linear(in_dim, 1)

    def forward(self, x):
        out = self.net(x)
        if self.skip:
            out = out + self.skip(x)
        return out  # [batch, 1]

Features

  • SiLU ReLU GELU activation options
  • Residual skip connection: ensures the tower can learn a linear function easily
  • BatchNorm on input (optional) for feature standardization
  • Dropout on hidden layers
  • in_dim=1 for main effects, in_dim=2 for GA2M interactions

LearnableMonotoneTransform

Monotone piecewise-linear feature normalization, initialized from data percentiles.

yknots = cumsum(softplus(raw_deltas)) / total  —  guarantees monotonicity via softplus

MonotonePWL Tower

Piecewise-linear with monotonicity constraint: all slopes ≥ 0

slopei = softplus(rawi) ≥ 0
  • Each segment has independent slope
  • Only constraint: slope ≥ 0 (monotone non-decreasing)
  • No concavity constraint — slopes can increase or decrease freely
  • Use for: pointwise objectives where higher feature value always means higher score (e.g., revenue, freshness)

ConcavePWL Tower

Monotone and concave: slopes are non-increasing — diminishing returns

slopeK = softplus(rawK)
slopei = slopei+1 + softplus(rawi)
⇒ slope0 ≥ slope1 ≥ … ≥ slopeK ≥ 0
Why concave matters:
Concave + modular = submodular function
⇒ Greedy selection gives (1 - 1/e) ≈ 63% of optimal
(Nemhauser et al. guarantee)

GA2M — Adding Pairwise Interactions

score(x) = ∑j fj(xj) + ∑(j,k) fjk(xj, xk) + bias

Interaction Selection

How to pick which feature pairs get interaction towers? Correlation-based selection.

pairs = select_interactions_correlation(
    X, y, top_k=50
)
# Returns: [(3, 7), (1, 12), ...]

model = GA2M_Paper(
    num_features=136,
    interaction_pairs=pairs,
    hidden_dims=[16, 8]
)
Algorithm:
  1. For each pair (j, k): compute interaction = x_j × x_k
  2. Measure |pearson_corr(interaction, y)|
  3. Sort by correlation, select top-K pairs

Complexity: O(D²) where D = number of features

ContextGAM — Query-Adaptive Weighting

score(x) = ∑j wj(x) · fj(xj) + bias  —  where w = softmax(context_net(x))

When to Use Which Model?

The Diversity Problem

Pure relevance ranking → homogeneous results. Users want variety.

Submodularity — Diminishing Returns

f(A ∪ {e}) - f(A) ≥ f(B ∪ {e}) - f(B)    when A ⊆ B

Adding item e to a smaller set gives more marginal value than to a larger set.

Greedy guarantee: For submodular functions, greedy selection achieves at least (1 - 1/e) ≈ 63% of the optimal solution. ConcavePWL towers enforce submodularity by construction.

Greedy Reranking Algorithm

def greedy_rerank(self, x, k=None):
    base = self.base_scores(x)  # [L]
    selected = []

    for step in range(k):
        candidates = remaining(x)
        # Compute set-dependent features
        gw = feature_computer.compute(
            candidates, selected, x
        )
        # Score through ConcavePWL
        div = diversity_towers(gw)
        # Total marginal gain
        gain = base[cand] + div
        # Select best
        best = argmax(gain)
        selected.append(best)

    return selected  # [k] indices

LambdaLoss — The Recommended Choice

Unified framework for NDCG-aware pairwise losses:

L = ∑i,j: yi > yj wij · log(1 + e-σ(si-sj))

Different weighing schemes:

  • RankNet: w = 1 (plain pairwise)
  • NDCGLoss1: w = G/D (gain/discount)
  • NDCGLoss2: refined ΔNDCG weights
  • LambdaRank: w = |Δpos| · |ΔG|
  • NDCGLoss2++: μ · NDCGLoss2 + LambdaRank

Java Inference — Zero ML Dependencies

CompiledPwlFunction — Specialized Evaluators

Switch on K (number of knots) to generate optimized if/else chains:

Generic (K > 6): Binary search

// O(log K) comparisons per evaluation
int idx = Arrays.binarySearch(xKnots, x);
double t = (x - xKnots[idx])
         / (xKnots[idx+1] - xKnots[idx]);
return yKnots[idx]
     + t * (yKnots[idx+1] - yKnots[idx]);

Compiled (K=3): Inlined constants

// All values inlined as final locals
final double x0=0.1, x1=0.5, x2=1.2;
final double y0=-0.3, y1=0.4, y2=0.7;
final double s0=1.75, s1=0.43;

if (x <= x0) return y0;
if (x >= x2) return y2;
if (x <= x1)
    return y0 + s0 * (x - x0);
return y1 + s1 * (x - x1);

Column-Major Scoring — Cache-Friendly

Performance: Column-major is 2-4x faster for large lists (1K+ docs). Feature column fits in L1 cache (10K doubles = 80KB).

SubmodularGamReranker — Lazy Greedy

Minoux lazy greedy (1978) exploits submodularity to skip recomputation:

  1. Compute base scores once (cached)
  2. Initialize priority queue with upper-bound gains
  3. For each of k positions:
    • Pop top candidate from queue
    • Recompute true marginal gain
    • If still best → select it
    • Otherwise push back, try next
  4. Submodularity guarantees: previous gain ≥ current gain
Budget control: Limit max evaluations per position.
10K candidates, k=40, budget=10 → ~400 evals (vs 400K naive).
1000x speedup for reasonable budgets.
